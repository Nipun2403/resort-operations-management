### SLIDE 7 — DIFFERENTIATOR 3: ZERO-TOUCH OBSERVABILITY
**Layout:** Three cards — Audit, Idempotency, Image Security

**Card 1 — ORM-Level Audit (CDC):**
```
SaveChangesAsync Override
        │
        ├─▶ Added    → NewValues (JSONB)
        ├─▶ Modified → OldValues + NewValues (JSONB diff)
        └─▶ Deleted  → OldValues (JSONB)
        
Enrichment: Actor (IAuditUserProvider) + Timestamp + Entity + PK
Storage: PostgreSQL JSONB (indexed, injection-safe)
Coverage: 18 entity types • Self-auditing • Zero attributes
```

**Card 2 — End-to-End Idempotency:**
```
X-Idempotency-Key (UUID) on EVERY mutation
        │
        ├─▶ Action Filter intercepts
        ├─▶ Key exists? → Replay cached response (status + body)
        ├─▶ New? → Execute → Store response in IdempotentRequest table
        └─▶ Cleanup Worker: 48h TTL
        
Race condition: PK conflict on insert → silent fall-through → cached response
Coverage: POST/PUT/PATCH globally • Opt-out attribute for Auth
```

**Card 3 — Magic-Byte Image Validation:**
```
Upload → SAS URL (15-min, Write+Create only)
        │
        ├─▶ Extension whitelist (jpg/png/webp)
        ├─▶ Size limit (10MB)
        ├─▶ Queue message → ImageValidationWorker (2s poll)
        ├─▶ Read first 512 bytes from blob
        ├─▶ Validate magic bytes:
        │     JPEG:  FF D8 FF
        │     PNG:   89 50 4E 47 0D 0A 1A 0A
        │     WebP:  52 49 46 46 ... 57 45 42 50
        ├─▶ Size mismatch check (declared vs actual)
        └─▶ Reject → Delete blob + Log reason
        
Workers: Validation • Orphan Cleanup (hourly) • Blob Cleanup (hourly)
```

**Speaker Notes:**
> "Three pillars of observability you didn't see. Audit: every change on every entity captured at the ORM layer — JSONB diff, impossible to bypass. Idempotency: every mutation carries a key — duplicate retry replays exact response, zero double-charges. Image security: we read magic bytes from the blob itself, not extensions. Renamed `.exe` → `.jpg` gets caught and deleted. Three background workers keep storage clean."
